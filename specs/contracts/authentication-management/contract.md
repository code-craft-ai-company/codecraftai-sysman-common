# Authentication-Management Contract

This is the cross-OS abstract contract for the
**authentication-management** feature. Every `codecraftai-sysman-*`
package that ships an authentication manager MUST honor this
contract.

The reference implementation is
[`codecraftai-sysman-linux-redhat/specs/3-authentication-management/`](../../../../../codecraftai-sysman-linux-redhat/specs/3-authentication-management/).
It wraps `authselect`, `/etc/pam.d/` drop-ins, `pwquality.conf`,
`faillock.conf`, `/etc/security/limits.d/`, and
`/etc/nsswitch.conf` through an `ICommandRunner`. This contract
generalises the verb set for OSes whose authentication stack is
PAM (Linux), OpenDirectory plus the macOS authorization database
(`/etc/pam.d/`, `/etc/authorization.plist`), or the Windows LSA
authentication package / local security policy
(`secpol.msc`, `Get-LocalUser`, `Set-LocalUser`).

---

## Scope

The authentication-management feature provides idempotent,
auditable control over the host's authentication configuration
above individual user accounts. It covers:

- Reading and writing the configuration of a named authentication
  subsystem (a PAM service name, an OpenDirectory node, or an
  LSA authentication-package configuration surface).
- Listing the authentication methods registered on the host.
- Enabling and disabling a named authentication method.
- Dry-run-aware writes.
- Elevation for writes; reads never elevate unless the OS
  requires elevation to inspect the configuration.

The feature does NOT manage individual user accounts or
passwords — that is `user-group-management`. It does NOT manage
directory bindings, realm joins, or Kerberos ticketing — that is
`identity-management`.

The feature is executed exclusively through an `ICommandRunner`.

## Verbs

Every OS implementation MUST expose an `AuthenticationManager`
class (the OS-prefixed variant — see §Naming) whose public
surface is the following set of verbs.

| Verb | Signature | Kind |
|------|-----------|------|
| `get_auth_config` | `(subsystem: str) → AuthConfig` | Read |
| `set_auth_config` | `(subsystem: str, config: AuthConfig) → AuthActionResult` | Write |
| `list_auth_methods` | `() → list[AuthMethodInfo]` | Read |
| `enable_method` | `(name: str) → AuthActionResult` | Write |
| `disable_method` | `(name: str) → AuthActionResult` | Write |
| `get_method_status` | `(name: str) → AuthMethodInfo` | Read |
| `apply_changes` | `() → AuthActionResult` | Write |

### Method-level invariants (writes)

1. **Idempotency guard.** `set_auth_config` MUST read the current
   configuration and compare; matching configuration MUST return
   `SKIPPED`. `enable_method` MUST return `SKIPPED` when the
   method is already enabled; `disable_method` MUST return
   `SKIPPED` when the method is already disabled or absent.
   `apply_changes` is operational and MUST NOT skip.
2. **Dry-run short-circuit.** `dry_run=True` MUST return `DRY_RUN`
   without invoking the runner.
3. **Error surface.** Failures MUST return `FAILED` with
   `exit_code`, `stdout`, `stderr`, and `command` populated.
4. **Atomicity.** When the OS provides a staging / apply model
   (e.g., `authselect apply-changes`, Windows policy commit),
   `set_auth_config`, `enable_method`, and `disable_method` MAY
   stage changes without applying. Callers MUST explicitly call
   `apply_changes` to commit. OS specs MUST document whether
   changes are staged or immediate.
5. **No silent overwrite.** On OSes where the canonical config
   was generated by a management tool (e.g., authselect marker on
   `/etc/pam.d/`), writes MUST raise
   `AuthenticationConfigError` rather than silently overwriting
   the managed file.

### Method-level invariants (reads)

1. **No elevation.** Reads MUST NOT pass `elevated=True` to the
   runner, except where the OS requires elevation to read
   authentication config.
2. **Typed errors.** `get_auth_config`, `list_auth_methods`, and
   `get_method_status` MAY raise `AuthenticationQueryError` for
   unexpected failures or, per the per-OS spec, return a synthetic
   record (e.g., `AuthMethodStatus(enabled=False, configured=False)`)
   so the caller can proceed without a try/except wrapper. An
   unknown subsystem or method MUST raise
   `AuthenticationSubsystemNotFoundError`. See the README
   "Implementation Conventions" graceful-read pattern.
3. **Pure parsing.** All parsing runs in pure Python.

## Data Models

Every OS implementation MUST expose these dataclasses and enum,
each prefixed with the OS name (see §Naming).

### `AuthActionStatus` (enum)

| Value | Meaning |
|-------|---------|
| `SUCCESS` | The command ran and succeeded. |
| `FAILED` | The command ran and returned non-zero, or a precondition was not met. |
| `SKIPPED` | The idempotency guard determined no action was needed. |
| `DRY_RUN` | Dry-run mode short-circuited the command. |

### `AuthConfig` (dataclass)

| Field | Type | Description |
|-------|------|-------------|
| `subsystem` | `str` | The subsystem this config belongs to (PAM service name, OpenDirectory node, LSA surface). |
| `profile` | `str \| None` | Selected profile / template name when applicable (e.g., authselect profile). |
| `features` | `list[str]` | Enabled feature flags / options. |
| `directives` | `dict[str, str]` | Named directive → value pairs (e.g., pwquality keys, PAM module options). |
| `raw` | `str \| None` | Verbatim config content for reporting; MAY be `None` on OSes without a single canonical file. |

### `AuthMethodInfo` (dataclass)

| Field | Type | Description |
|-------|------|-------------|
| `name` | `str` | Method / module / authentication package name. |
| `enabled` | `bool` | Currently enabled state. |
| `available` | `bool` | Installed / registered on the host. |
| `description` | `str \| None` | Human-readable description when available. |

### `AuthActionResult` (dataclass)

| Field | Type | Description |
|-------|------|-------------|
| `status` | `AuthActionStatus` | Outcome category. |
| `subsystem` | `str \| None` | Subsystem or method name acted upon. |
| `detail` | `str \| None` | Human-readable detail. |
| `exit_code` | `int \| None` | Runner exit code. |
| `stdout` | `str \| None` | Captured stdout. |
| `stderr` | `str \| None` | Captured stderr. |
| `command` | `list[str] \| None` | The argv that was (or would have been) executed. |

### Exceptions

| Exception | Raised When |
|-----------|-------------|
| `AuthenticationQueryError` | A read fails unexpectedly. |
| `AuthenticationConfigError` | A write would overwrite a managed config without explicit opt-in, or the supplied `AuthConfig` is malformed for the subsystem. |
| `AuthenticationSubsystemNotFoundError` | An unknown subsystem or method name is passed. |

### `AuthenticationManagerConfig` (dataclass)

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `dry_run` | `bool` | `False` | When `True`, writes short-circuit. |
| `elevated` | `bool` | `False` | When `True`, writes pass `elevated=True` to the runner. |
| `allow_unmanaged_overwrite` | `bool` | `False` | When `True`, writes may overwrite tool-managed config files. Defaults to a safe `False`. |

## Subsystem Mapping

The abstract `subsystem` string maps to each OS's native
addressing:

| OS | Native concept | Notes |
|----|----------------|-------|
| Red Hat Enterprise Linux | PAM service name (`sshd`, `system-auth`, `password-auth`, ...) | Canonical. `authselect` profile surface uses the pseudo-subsystem `"authselect"`. |
| Ubuntu | Same as RHEL; `authselect` is replaced by `pam-auth-update` surface under `"pam-auth-update"`. | — |
| macOS | OpenDirectory node path plus `/etc/pam.d/<service>` drop-ins; `subsystem` is either a PAM service name or the pseudo-subsystem `"opendirectory"` / `"authorization"`. | — |
| Windows | LSA authentication package name (e.g., `"Kerberos"`, `"NTLM"`), or the pseudo-subsystem `"LocalSecurityPolicy"` for password-policy directives read via `secpol` / `Get-LocalSecurityPolicy`. | — |
| UEFI | N/A | UEFI has no user-authentication subsystem. The contract does not apply. |

Each OS spec MUST include a Subsystem-Mapping section stating
which subsystem names are supported and how unknown names
surface errors.

## Elevation

| Situation | Behavior |
|-----------|----------|
| Config `elevated=True`, write method | Pass `elevated=True` to the runner. |
| Config `elevated=True`, read method | Do NOT pass `elevated=True`, except where the OS requires it. |
| Config `elevated=False` | Never pass `elevated=True`. |
| OS mechanism | `sudo` on RHEL/Ubuntu/macOS; Administrator token / UAC on Windows. |

## Execution Model

```
        Maintenance coordinator
                │
                │  instantiates + injects runner, config
                ▼
        <Os>AuthenticationManager
                │
                │  .run(argv, elevated=…, capture_output=True)
                ▼
          ICommandRunner
                │
        ┌───────┴────────┐
        ▼                ▼
  LocalCommandRunner   SSHCommandRunner
        │                │
        └────────┬───────┘
                 │  aspects compose here
                 ▼
        PersistenceAspect, RetryAspect, TimeoutAspect
```

All OS implementations MUST:

1. Accept an `ICommandRunner` and an
   `AuthenticationManagerConfig` in their constructor.
2. Never construct their own subprocess.
3. Not hold state across calls beyond the config.
4. Be safe under any aspect composition on the runner.

## Aspect Composition

Aspect behavior MUST be transparent to the manager:

- A manager tested with a `MockCommandRunner` and no aspects MUST
  produce the same `AuthActionResult` sequence when driven by a
  real runner with aspects attached, modulo retry-induced timing.
- Retry aspects are permitted to flip `status` from `FAILED` to
  `SUCCESS`.
- Persistence aspects MUST NOT mutate the result.

---

## Tests

Each OS implementation MUST include at minimum:

1. One command-construction test per write verb.
2. One idempotency test per write proving `SKIPPED` on matching
   state.
3. One dry-run test per write verb proving the runner is not
   invoked.
4. One `get_auth_config` parser test per representative
   subsystem.
5. One `list_auth_methods` parser test covering the OS's native
   enumeration output.
6. One managed-overwrite test proving
   `AuthenticationConfigError` is raised when
   `allow_unmanaged_overwrite=False` and the target file is
   tool-managed.
7. One unknown-subsystem test proving
   `AuthenticationSubsystemNotFoundError` is raised before the
   runner is invoked.
8. One elevation test proving writes pass `elevated=True` and
   reads do not, when configured.

## Out of Scope for the Base Contract

The following are intentionally NOT in the contract. They MAY be
added by any OS implementation as extensions but are not required
for contract conformance:

- Per-user account attributes, password hashing, and SSH key
  management — covered by `user-group-management`.
- Directory-service binding and realm join — covered by
  `identity-management`.
- SSHD-level configuration — covered by
  `ssh-server-configuration`.
- Kerberos ticket lifecycle — covered by `identity-management`.
- MFA token enrolment.
- Password-vault / secret-store integration.

## Implementation Drift

Phase 3 cross-OS implementations surfaced these intentional
deviations from the contract.

- **No `IFileOperator`.** Ubuntu, macOS, and Windows all route
  PAM/`/etc/nsswitch.conf`/LSA configuration reads and writes
  through `ICommandRunner` using `cat` / `tee` / `Get-Content` /
  `Set-Content` rather than a separate `IFileOperator`.
- **macOS `OpenDirectory` divergence.** macOS uses
  `dscl` / `dsconfigad` and exposes auth-method state through a
  pair-shaped record that does not align with Linux PAM stack
  semantics. The `MacosAuthMethodStatus` shape carries
  `directory_node` and `protocol` fields that are absent on Linux.
- **Windows LSA exposure.** Windows surfaces auth-method state as
  LSA package status rather than PAM-stack rules; the
  `WindowsAuthMethodStatus` field set deliberately differs from
  Ubuntu's PAM-shaped record.
